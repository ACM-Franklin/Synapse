Wireframe pack · low-color · structure-forward

A frontend for Synapse, the community engagement engine for one Discord guild.

Synapse is not a SaaS, not multi-tenant, and not a moderation tool. It is one instance, one guild, and an immutable event lake on which a configurable rule engine awards XP and currency. The product earns its keep on transparency, explainability, and admin control. The frontend has to feel that way too.

Information architecture

Admin moderequires admin role

  • 01 Overview — guild health, scanner state, rule activity →
  • 02 Event lake — tail · search · charts · taxonomy →
  • 03 Rules — list, editor, evaluation log →
  • 04 Members — directory + member detail with reward audit →
  • 05 Channels & categories — opt in/out, scan provenance →
  • 06 Seasons — windows + seasonal stats →
  • 07 Historical scan — channel pick · range · ingest vs reward →
  • 08 Settings — currency names, admin roles, instance state →

Member modeguild members only

  • M1 My profile — level, currencies, recent rewards →
  • M2 Why did I get this? — reward trace per event →
  • M3 Leaderboard — current season, all-time, by metric →
  • M4 Other members — public profiles (read-only) →
  • M5 Seasons — past standings →
  • F1 Achievements (future) ⌖
  • F2 Marketplace + inventory (future) ⌖

Auth is Discord OAuth. Guild non-members see a connect screen. Members land on M1. Admins get a mode switcher in the topbar. One product ambiguity: a doc proposes a public unauthenticated leaderboard — designed as an opt-in variant, not the default.
